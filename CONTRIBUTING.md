# Contributing

Suggestions and corrections are welcome. Keep the project practical and tool-neutral where possible.

## Guidelines
- Prefer official, publicly accessible learning resources.
- Mark paid, licensed, legacy, or access-restricted tools clearly.
- Separate required core skills from optional electives.
- Keep learning steps actionable and define evidence of completion.
- Do not add personal credentials, private data, copyrighted course material, or secrets.
- Test links and examples before opening a pull request.

## Suggested change workflow
1. Open an issue describing the learning gap or proposed improvement.
2. Make a focused change and explain why it improves the learning path.
3. Check formatting, links and examples.
4. Submit a pull request with a short summary and testing notes.
