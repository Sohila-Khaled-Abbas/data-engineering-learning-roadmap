## GitHub roadmaps and project examples

### [Homosaaa — Data Engineering Mentorship Roadmap](https://github.com/homosaaa/homosaaa-data-engineering-roadmap)
**Focus:** SQL, Python, data warehousing/modeling, cloud fundamentals, Git/GitHub, Docker, learning channels, and Data Engineering Zoomcamp.

**How to use it:** choose one supplementary resource after completing the matching phase. The project links out to external materials; verify current pricing and course availability on the original sites.

### [IEEE ManCSC — Data Engineering Roadmap 2025](https://github.com/Welloz03/Data-Engineering-Roadmap-IEEEManCSC-2025)
**Focus:** a general roadmap and a week-by-week version paced around approximately eight study hours per week, covering SQL, Python, warehouse/ETL/BI, Linux, dbt, orchestration, cloud, and big data.

**How to use it:** use the weekly schedule as a pacing reference, not as another mandatory checklist. Adapt weeks to your current level and available time.

### [Obsidian Vault Roadmap](https://github.com/ahmedashraffcih/Obsidian-Vault-Roadmap)
**Focus:** graphical data engineering roadmap maps and a visual way to organize topic relationships.

**How to use it:** use the diagrams to see dependencies and create your own linked Obsidian notes; keep your own written explanations and practice evidence.

### [DataBurst — Data Engineering Roadmap](https://github.com/data-burst/data-engineering-roadmap)
**Focus:** a broad data engineering roadmap plus a separate cloud data engineering roadmap and a guide that encourages learning concepts before chasing every product.

**How to use it:** consult it when deciding which concepts are core and which tool alternatives are optional. Do not attempt to master every technology shown.

## A practical way to use these sources

1. Follow the relevant phase in [the main roadmap](../ROADMAP.md).
2. Pick **one** extra resource from this page only if you need a different explanation, visual map, or additional exercises.
3. Build something small with the topic: a query, script, model, pipeline, diagram, or report.
4. Save evidence to your own learning repository.
5. Add a source to your notes only after you verify the current URL and any login, license, fee, or access limitations.

> **Attribution and maintenance:** These are external links, not materials owned or maintained by this repository. This catalog summarizes the intended use at a high level; it does not copy other repositories' roadmaps or assets. Respect each source's license and attribution rules, and check that shared pages are still available before relying on them.
